# Вклад в проект

## Workflow внесения изменений

1. **Создайте ветку** от `master`:
   ```bash
   git checkout master
   git pull origin master
   git checkout -b feature/название-ветки
   ```

2. **Внесите изменения** и закоммитьте:
   ```bash
   git add .
   git commit -m "краткое описание изменений"
   ```

3. **Пушьте ветку** на сервер:
   ```bash
   git push origin feature/название-ветки
   ```

4. **Создайте Merge Request (MR)**:
   - Откройте `https://gitverse.ru/sayr/dba/merge_requests/new`
   - Base branch: `master`
   - Head branch: `feature/название-ветки`

5. **Дождитесь ревью** и устранения замечаний.

6. **Слейте MR** в `master` после одобрения.

## Правила оформления коммитов

- Используйте настоящее время: «add», а не «added»
- Первая строка — заголовок до 50 символов
- Разделитель — пустая строка
- Описание — по желанию, если заголовок неочевиден

Пример:
```
add lec_14 about backup strategies
```

## Правила оформления Merge Request

- Заголовок: краткое описание изменений
- Описание: что изменено, зачем, как тестировать
- Связанные issue: укажите номер через `#N`
- Чек-лист:
  - [ ] Изменения протестированы
  - [ ] Документация обновлена (если нужно)
  - [ ] Нет конфликтующих файлов

## Требования к коду

- Файлы в кодировке UTF-8
- Markdown-файлы: мягкие переносы строк (soft wrap)
- Избегайте бинарных файлов в репозитории

## Ответственность

Ревьюеры отвечают в течение 48 часов. Если MR не рассматривается дольше — напишите автору MR.
