## 2. Сценарий A: Повреждение данных

**Признаки:** Обнаружены повреждённые данные (ложные заказы, удалённые клиенты)

### Checklist для системного аналитика:

- [ ] Подтвердить факт повреждения данных
- [ ] Определить таблицу/диапазон данных
- [ ] Оценить масштаб (сколько строк затронуто)
- [ ] Сообщить дежурному DBA
- [ ] Зафиксировать время обнаружения
- [ ] Зафиксировать таблицу и количество affected строк

### Действия DBA:

1. Определить точку восстановления (до повреждения)
2. Остановить приложения к БД
3. Восстановить из бэкапа + PITR до нужного момента
4. Проверить целостность данных
5. Сообщить аналитику о готовности
6. Запустить приложения

### Время восстановления:

| Этап | Время |
|------|-------|
| Обнаружение и подтверждение | 15 мин |
| Восстановление бэкапа | 30 мин |
| PITR до нужной точки | 30 мин |
| Проверка целостности | 15 мин |
| **Итого RTO** | **~1.5 часа** |

## 3. Сценарий B: Отказ сервера

**Признаки:** Сервер не отвечает, SSH недоступен

### Checklist для системного аналитика:

- [ ] Подтвердить недоступность сервера
- [ ] Сообщить дежурному DBA и сисадмину
- [ ] Зафиксировать время простоя

### Действия DBA:

1. Проверить статус сервера (через IPMI / хостинг-панель)
2. Если сервер недоступен — запросить замену у хостинг-провайдера
3. На новом сервере:
   - Установить PostgreSQL той же версии
   - Восстановить из basebackup
   - Восстановить WAL-архив до последней точки
4. Проверить работоспособность
5. Обновить DNS / IP если нужно

### Время восстановления:

| Этап | Время |
|------|-------|
| Запрос замены сервера | 1-2 часа |
| Установка PostgreSQL | 15 мин |
| Восстановление basebackup | 30 мин |
| WAL replay | 30 мин |
| Проверка | 15 мин |
| **Итого RTO** | **~3 часа** |

| Сценарий | Источник восстановления | Точка | RTO |
|----------|------------------------|-------|-----|
