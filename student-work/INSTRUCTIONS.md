# Инструкция для студентов

Как создать свою ветку, добавить работу и отправить Merge Request.

## Зачем `student-work/`

Основной проект — учебный курс. Файлы студентов (лабы, доклады, дампы, логи) не являются частью курса и не должны быть в `main`.

Папка `student-work/` — это «песочница»:
- Вы кладёте сюда свои файлы в **своей ветке**.
- Это не загромождает основной проект.
- После проверки преподаватель мержит вашу ветку — работа попадает в историю.

## Шаг 1. Создайте свою ветку

Каждая группа работает в **своей ветке**. Название по шаблону:

```
group/<группа>-<тип>
```

Примеры:

```bash
# Для дневной группы Пи 41 (лабораторные)
git checkout -b group/pi-41-labs

# Для заочной группы Пи з-42 (доклады)
git checkout -b group/pi-z-42-reports
```

## Шаг 2. Добавьте файлы в свою папку

Положите файлы в папку вашей группы:

```
# Лабораторные работы
student-work/labs/<группа>/

# Доклады
student-work/reports/<группа>/
```

Пример:

```bash
# Для Пи 41 — лабораторная №1
cp student-work/templates/lab_01_erd.mermaid student-work/labs/Pи 41/lab_01_ivanov.md
```

## Шаг 3. Закоммитьте изменения

```bash
git add student-work/labs/Pи 41/
# или
git add student-work/reports/Pи 42/

git commit -m "Добавлена лабораторная №1 — Пи 41 — Иванов И.И."
```

## Шаг 4. Отправьте ветку на сервер

```bash
git push -u origin group/pi-41-labs
```

## Шаг 5. Создайте Merge Request

1. Откройте репозиторий на GitHub/GitLab.
2. Нажмите **New Merge Request** / **New Pull Request**.
3. Выберите вашу ветку (`group/pi-41-labs`) в качестве источника.
4. Целевая ветка: `main`.
5. Заполните описание MR (см. примеры ниже).
6. Нажмите **Create MR**.

# Лабораторные работы

## Что сдавать

Каждая лабораторная описана в папке `labs/lab_NN/`. Артефакты — файлы, которые студент создаёт по ходу выполнения.

**Шаблоны всех артефактов** лежат в `student-work/templates/`. Скопируйте нужный шаблон, заполните своими данными.


# Доклады

## Что сдавать

Студенты, выбравшие доклад, оформляют его по требованиям из [docs/reports.md](../docs/reports.md).

### Варианты выполнения

| Вариант | Что нужно |
|---------|-----------|
| **Только доклад** | README.md + диаграммы + сравнение. Баллы перераспределяются на устные ответы. |
| **Доклад + демонстрация** | README.md + диаграммы + сравнение + рабочая система (Docker/SQL). |

### Обязательный минимум

| Элемент | Обязательно |
|---------|-------------|
| Формат | Markdown (`.md`) |
| Диаграммы | **Mermaid** + **PlantUML** |
| Примеры кода | SQL/bash — без скриншотов из IDE |

### Структура README.md доклада

```markdown
# Название темы

## 1. Цель и актуальность
## 2. Архитектура (Mermaid-диаграмма)
## 3. Установка и развёртывание
## 4. Демонстрация (SQL-запросы с реальным выводом)
## 5. PlantUML-диаграмма
## 6. Сравнение с альтернативами
## 7. Ограничения и когда НЕ применять
## 8. Ссылки
```

## Формат именования

```
report_NN_фамилия.md
```

Пример: `report_05_petrov.md`

## Пример MR для доклада

**Заголовок:** Доклад №5 — Пи з-42 — Петров П.П. — TimescaleDB

**Описание:**
```
Группа: Пи з-42
Студент: Петров Петр Петрович
Доклад: №5 — TimescaleDB: временные ряды в PostgreSQL
Файл: student-work/reports/Pи з-42/report_05_petrov.md
Вариант: доклад + демонстрация (docker-compose.yml, demo.sql)
```

## Сроки

- Ссылку на MR кидаете в чат группы в Telegram до начала доклада
- Доклад: 15 мин выступление + 5 мин вопросы

# Если нужно добавить ещё одну работу

Создайте новую ветку:

```bash
git checkout -b group/pi-41-labs-2
# добавьте файлы в ту же папку student-work/labs/Pи 41/
git add student-work/labs/Pи 41/
git commit -m "Лабораторная №2 — Пи 41 — Иванов И.И."
git push -u origin group/pi-41-labs-2
# создайте MR
```

## Важные замечания

- Не редактируйте чужие папки.
- Не создавайте ветки без согласования с преподавателем.
- После мёржа MR ветка может быть удалена.
- Убедитесь, что файлы открываются и форматирование в порядке перед отправкой MR.
