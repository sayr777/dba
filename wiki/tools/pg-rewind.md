# pg_rewind

`pg_rewind` — утилита PostgreSQL для быстрого возврата старого primary в кластер после failover: синхронизирует `PGDATA` с новым primary только по изменившимся блокам, без полной копии кластера.

---

## 1. Зачем нужен

После аварийного переключения старый primary может содержать транзакции, которых нет на новом primary. Ветви истории WAL расходятся (**Timeline Divergence**), и просто запустить старый сервер репликой нельзя.

`pg_rewind` находит точку расхождения и «отматывает» старый узел до состояния, совместимого с новым primary. Это быстрее, чем `pg_basebackup` на сотни гигабайт: копируются только изменённые блоки.

---

## 2. Как работает

1. Находит в истории WAL точку бифуркации — момент, когда timeline старого и нового primary разошлись.
2. Сравнивает карты блоков `PGDATA` старого узла и нового primary.
3. Копирует с нового primary только те блоки, которые изменились после расхождения.
4. Откатывает незавершённые транзакции и переводит старый узел в состояние, пригодное для запуска в режиме standby.

---

## 3. Обязательные условия

- **`wal_log_hints = on`** на всех узлах кластера **или** контрольные суммы страниц (`initdb --data-checksums`). В PostgreSQL 18 контрольные суммы включаются `initdb` по умолчанию.
- На новом primary (или в WAL-архиве) должны быть доступны WAL-сегменты с точки расхождения.
- Старый узел перед запуском `pg_rewind` должен быть остановлен.
- Утилита запускается от пользователя ОС, владеющего каталогом `PGDATA`.

---

## 4. Команда

```bash
pg_rewind \
  --target-pgdata=/var/lib/postgresql/18/main \
  --source-server="host=new-primary port=5432 user=replicator dbname=postgres"
```

После успешного завершения на старом узле нужно:

1. Создать файл `standby.signal`.
2. Прописать `primary_conninfo` на нового primary.
3. Запустить PostgreSQL и проверить, что узел работает как standby.

```ini
# postgresql.auto.conf на бывшем primary
primary_conninfo = 'host=new-primary port=5432 user=replicator'
```

---

## 5. Patroni

В [[tools/patroni]] утилита `pg_rewind` используется для автоматического восстановления бывшего primary. Чтобы Patroni мог её вызывать, в конфигурации должен быть включён `use_pg_rewind`, а на узлах — `wal_log_hints` или контрольные суммы.

> **Ограничение:** `pg_rewind` не заменяет резервное копирование. Если WAL с точки расхождения утерян или `PGDATA` повреждён, узел пересоздают через [[tools/pg-basebackup]].
