# pg_upgrade

`pg_upgrade` — утилита обновления кластера PostgreSQL между мажорными версиями (например, 17 → 18) без полного логического дампа и восстановления; переносит каталоги данных и обновляет системные каталоги.

---

## 1. Когда нужен

- Переход на новую мажорную версию (17 → 18).
- Минорные обновления (18.1 → 18.2) не требуют `pg_upgrade`: достаточно заменить бинарники.

---

## 2. Подготовка

1. Прочитать release notes и проверить несовместимости.
2. Сделать и проверить резервную копию.
3. Установить новую версию рядом со старой.
4. Проверить расширения: часть может требовать обновления.
5. Оценить время простоя: `pg_upgrade` останавливает старый кластер.

---

## 3. Команды

```bash
# Проверка без изменений
pg_upgrade \
  -b /usr/lib/postgresql/17/bin \
  -B /usr/lib/postgresql/18/bin \
  -d /var/lib/postgresql/17/main \
  -D /var/lib/postgresql/18/main \
  --check

# Выполнение
pg_upgrade \
  -b /usr/lib/postgresql/17/bin \
  -B /usr/lib/postgresql/18/bin \
  -d /var/lib/postgresql/17/main \
  -D /var/lib/postgresql/18/main
```

| Флаг | Смысл |
|---|---|
| `-b` | Каталог bin старой версии |
| `-B` | Каталог bin новой версии |
| `-d` | Старый `PGDATA` |
| `-D` | Новый `PGDATA` |
| `--check` | Только проверить совместимость |
| `-j` | Параллельные workers |
| `--link` | Жёсткие ссылки вместо копирования (быстрее, но старый кластер нельзя использовать) |

---

## 4. После обновления

```sql
-- Обновить расширения
ALTER EXTENSION pgaudit UPDATE;
ALTER EXTENSION pg_stat_statements UPDATE;

-- Собрать статистику
ANALYZE;
```

Затем:

- запустить `vacuumdb --analyze-only`;
- проверить приложение;
- обновить строки подключения;
- снять новый `pg_basebackup`;
- обновить runbook.

---

## 5. Альтернатива без простоя

Логическая репликация:

1. Поднять кластер новой версии.
2. Настроить публикацию на старом и подписку на новом.
3. Дождаться синхронизации.
4. Переключить трафик.
5. Остановить старый кластер.

Минусы: не реплицируются DDL и последовательности; нужна ручная подготовка схемы.
